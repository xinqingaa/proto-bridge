# 迁移说明书质量标准

本文档定义一份理想的 `migration-spec.md` 应该达到什么效果。

## 1. 核心目标

一份合格的迁移说明书应该让开发者或 AI 工具回答这些问题：

- 这个页面要实现什么业务目标？
- 原型页面由哪些 UI 区块组成？
- 哪些状态、事件、列表、弹层、条件渲染需要迁移？
- 在 YouFi Flutter 中应该落到哪个模块、哪些文件、哪种结构？
- 需要复用哪些路由、主题、i18n、资源和公共组件？
- 哪些信息已经确定，哪些只是推断，哪些必须人工确认？

## 2. 质量分级

### Bronze：当前可生成

- 能定位原型 route、screenId、Vue 文件。
- 能读取 notes 和 i18n。
- 能给出基础 token 映射。
- 能推荐一个 Flutter 模块。
- 能生成基础 Widget 拆分和人工确认项。

### Silver：近期目标

- 页面结构来自真实 Vue template，而不是固定模板。
- 状态与交互来自 Vue script 和 template 指令。
- 能列出建议新增或修改的 Flutter 文件。
- 能把 i18n key、资源、按钮、列表和 UI 区块关联起来。
- 能给出具体实现任务清单。
- 能生成可直接交给 AI 工具的实现提示词。

### Gold：后续目标

- 能结合运行时 DOM 和截图校对布局。
- 能识别目标 Flutter 模块内最相似页面并总结可复用写法。
- 能输出更准确的 Controller 字段、接口参数、路由参数、埋点和异常态建议。
- 能生成独立 `llm-prompt.md`，并保留 `migration-spec.md` 作为人工 review 文档。

## 3. 必备章节

### 3.1 迁移摘要

必须包含：

- 页面名称、route、screenId、Vue 文件。
- 推荐 Flutter 模块。
- 推荐实现形态。
- 复杂度和是否可直接进入实现。
- 最大阻塞点。

### 3.2 事实来源

必须列出本次文档依据了哪些信息：

- 原型配置文件。
- Vue SFC 文件。
- notes 文件。
- i18n JSON。
- Flutter 路由、模块、资源、翻译、通用组件扫描结果。
- 可选 screenshot / DOM snapshot。

如果某类来源缺失，必须说明缺失影响。

### 3.3 页面业务理解

必须尽量回答：

- 页面给用户解决什么问题？
- 页面展示哪些核心数据？
- 用户能触发哪些主要动作？
- 是否涉及交易、开户、资金、权限、风控等高风险流程？

无法确定时，要输出“需要从 notes / 产品 / Vue mock 数据确认”。

### 3.4 UI 结构拆分

必须从上到下描述页面区块：

- AppBar / 顶部导航。
- Header / Summary。
- Tab / Filter。
- Form / Input。
- List / Card / Table。
- Empty / Loading / Error。
- BottomBar。
- Dialog / Sheet / Toast。

每个区块应说明来源、职责和 Flutter Widget 建议。

### 3.5 状态与交互

必须提取并说明：

- 原型状态变量。
- computed 或派生状态。
- 点击、输入、切换、提交、关闭等事件。
- 条件渲染和列表渲染。
- Loading、empty、error、disabled、selected 等状态。

当前无法提取时，不能只写“待确认”，而要写“缺少哪类分析能力”。

### 3.6 Flutter 落地计划

必须包含：

- 目标模块路径建议。
- 可能新增或修改的 View / Controller / Binding / Model / Widget 文件。
- 路由注册建议。
- Controller 状态字段建议。
- Widget 拆分建议。
- 与现有相似页面的复用建议。

### 3.7 i18n 和资源

必须包含：

- 原型 i18n key 表。
- Flutter `.tr` 使用建议。
- 资源引用来源。
- Flutter asset 目标目录建议。
- 暗色模式资源风险。

### 3.8 Token 和视觉

必须包含：

- 已命中的颜色、字体、间距或圆角 token。
- 未命中的 token 和处理建议。
- 需要通过截图或人工确认的视觉差异。

### 3.9 风险和人工确认项

风险必须具体，例如：

- notes 缺失导致业务意图不完整。
- 原型 mock 数据无法确认真实接口。
- 交易类操作需要确认风控和权限。
- Flutter 模块中没有相似页面可复用。

人工确认项必须能被执行，例如：

- “确认 `xxx` 按钮点击后跳转到哪个 Flutter route”。
- “确认 `fundCode` 来自路由参数还是接口返回”。
- “确认 `empty` 状态使用现有 `CommonEmpty` 还是模块自定义组件”。

### 3.10 AI 实现提示词

必须能直接复制给 AI coding 工具，包含：

- 目标仓库和模块。
- 输入上下文摘要。
- 文件改动范围。
- 实现步骤。
- 不要做的事情。
- 验收命令或人工验证步骤。

## 4. 输出原则

- 事实、推断、待确认要分开写。
- 不要把 Vue DOM 逐行翻译成 Flutter Widget。
- 不要输出无法执行的空泛建议。
- 不要把 remote Git、adapter 架构等未来方向混入当前迁移说明书。
- 缺少上下文时，要说明缺口和下一步补齐方式。
