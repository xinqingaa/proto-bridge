# 产品文档与动效证据交付优化计划

状态：2026-10-22 按用户决定收敛。旧文档快照/MCP 与真实动效平台方案不再是当前任务的完成条件。现行采集规则见 [采集链路](../architecture/capture-pipeline.md)。

## 当前工作

当前只有两项交付：解除 DS 原文件重复归档对页面采集的阻塞；在独立 yike 工程的 docs 整理产品说明、逻辑与交互、UI 与动效说明，以及已知缺口。具体文件由该工程本地文档索引拥有。

产品文档直接通过文件读取，不登记文档 Catalog，不通过 MCP 获取，不建立文档 Snapshot 或文档读取 Tool。生成 Flutter target 时自动复制对应原型文档留到后续实现；当前由用户手动移动或复制，本批不修改生成脚本。

## 已有问题与保留事项

语义身份的大小写敏感驼峰支持已经存在，继续由 Core 负责校验。此前 yike 表盘说明的 theme.mode-divergence 已修复，不作为本批新增工作。保存失败仍误报成功、异常关闭进度损失和 Flutter 业务存储缺口在 yike 本地文档如实保留，不顺带改变业务规则。

## 延期与替代

| 原计划 | 当前决定 |
| --- | --- |
| M2 文档声明、Catalog、快照、预览、MCP 固定读取 | 由本地职责文档替代；不建设这条链路 |
| M3/M4 真实指针、动效时间采样、帧存储、时间轴和 MCP | 延期；当前仅整理 UI/动效意图，静态采集不证明正常运动过程 |
| 文档随固定 Handoff 自动发现 | 改为先读 Target 本地 docs，再经 MCP 读固定页面 Evidence |
| M0/M5/M6 围绕新文档/动效 Contract 的平台升级 | 随对应能力延期；当前仍验证采集历史兼容与已改链路 |
| Flutter 脚手架自动复制文档 | 后续独立任务，本轮手工移动/复制 |

原 18–27 人日平台投入与业务文档/动效 3–5 人日估算不再适用于本轮，不继续按旧批次推进。后续真实动效立项时先验证 CSS/JS/SVG 的时间控制与采样精度，再确定协议、预算、固定引用和消费者能力；正式产物必须区分设计意图、运行观测与 Target 验证。

## 完成与风险边界

当前完成要求为 DS 重复归档依赖解除、页面实际缺图仍可见、首 Bundle 到 Handoff 回归可复核，以及本地职责文档完整可读且不掩盖已知偏差。新文档不自动绑定 Handoff 版本，冲突需保留双方来源。不得将本轮描述为文档/动效 MCP 平台已建成。
