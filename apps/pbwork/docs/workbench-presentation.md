# Workbench 主题与组件展示规范

本文定义 PBWork Workbench 左侧导航的「设计基础」和「组件」两个入口的展示组织方式。

## 规范边界

本文是两个入口的信息组织与人工验收依据。设计基础已按用户要求回归改造前页面；本文的资源目录与主题详情属于后续目标，尚未作为正式页面交付。原型组件扩展登记和完整组件手机舞台也仍待收敛。不能因本文存在就声称登记 API 或自动门禁已实现。迁移批次与退出标准见[收敛计划](../../../docs/roadmap/workbench-presentation-convergence.md)。主题解析和 Evidence 语义沿用现有 Contract，本文不新增 Core Schema。

## 背景

平台升级完成后，PBWork 支持多主题和原型扩展能力：

- **多主题**：DS 基础主题包 + 每个原型可以有自己的主题包（对基础的差异化调整）
- **原型扩展**：DS 基础组件 + 原型可以对组件做变体 + 原型可以有自有组件

需要在 Workbench 中清晰展示这些层次，让用户能够：
1. 了解 DS 提供的基础能力（Token 和组件）
2. 查看某个原型做了哪些定制和扩展
3. 理解基础层与扩展层的关系

## 展示原则

### 1. 按层级分

- **基础层（DS）**：所有原型共享的 DS 基础主题包和 DS 基础组件
- **扩展层（原型）**：按原型分组，展示每个原型的主题定制和组件扩展

### 2. 按内容分

- **设计基础（Token）**：色彩、字体、间距、圆角、材质、动效等 Token 系统
- **组件（Component）**：可复用的 UI 组件及其变体

### 3. 资源目录进入详情

先选择基础资源或某个原型扩展，再查看详情。详情页不提供跨基础 DS、演示包和其它原型的“查看范围”切换；资源切换通过目录、面包屑或返回完成。当前资源包含多个主题时，允许选择包内主题和浅深模式。组件默认主题由资源归属确定。

样例包仅放在明确标注“仅演示”的辅助验证入口，不与正式基础资源、原型扩展并列，不绑定正式原型。主题效果对比集中在设计基础；组件中的辅助对比不能改变资源归属。

### 4. 原型扩展始终标注基础关系

当展示原型扩展时，必须清晰标注：
- 原型主题基于哪个基础主题包
- 与基础的差异项数
- 原型组件变体基于哪个 DS 基础组件

## 信息架构

### 「设计基础」入口

```
设计基础
├─ 基础主题包 (pbwork-base)
│  ├─ 色彩系统
│  ├─ 字体系统
│  ├─ 间距系统
│  ├─ 圆角与材质
│  └─ 动效参数
│
└─ 原型主题包 (按原型分组)
   └─ [原型名称]
      ├─ 基于：pbwork-base / [theme-name]
      ├─ 与基础差异：N 项
      └─ 差异明细
```

**点击基础主题包** → 展示基础 Token 系统的完整键值和样板
**点击原型主题包** → 展示该原型主题与基础的差异对比

### 「组件」入口

```
组件手册台
├─ DS 基础组件 (数量从 Registry 计算)
│  ├─ Action 类
│  │  ├─ Button
│  │  ├─ IconButton
│  │  └─ ...
│  ├─ Input 类
│  │  ├─ TextField
│  │  ├─ Select
│  │  └─ ...
│  └─ ...
│
└─ 原型扩展 (按原型分组)
   └─ [原型名称]
      ├─ 变体
      │  └─ Button "警报按钮"（基于 DS Button）
      └─ 自有组件
         └─ CustomGauge
```

**点击 DS 基础组件** → 展示该组件在基础主题下的能力、状态、尺寸和交互预览
**点击原型扩展** → 展示该原型的变体/自有组件在**该原型主题**下的样子

## 展示内容规则

### 完全遵循 DS 基础的原型

如果原型：
- 主题包与基础没有差异（或者使用 pbwork-base/default）
- 没有组件变体
- 没有自有组件

则：
- **设计基础**：不显示该原型的主题包条目
- **组件**：不显示该原型的扩展条目

### 有主题定制但无组件扩展的原型

如果原型：
- 主题包对基础有差异
- 但没有组件变体和自有组件

则：
- **设计基础**：显示该原型的主题包条目，标注差异项数
- **组件**：不显示该原型的扩展条目

### 有组件扩展的原型

如果原型：
- 有组件变体或自有组件

则：
- **组件**：必须显示该原型的扩展条目
- **设计基础**：如果有主题定制也显示；如果没有则不显示

## 实现要点

### 数据源与声明

- **基础主题包**：`apps/pbwork/src/design-system/themes/pbwork-base/`
- **原型主题包**：`apps/pbwork/src/prototypes/{prototypeId}/theme/` （如果存在）
- **DS 基础组件**：`apps/pbwork/src/design-system/components/registry.ts`
- **原型扩展**：以显式登记为依据，关联原型所有权、组件实现和预览。现有 Prototype/Screen Registry 不等于已经支持组件扩展目录；具体登记类型与校验随正式实现一并落地，不能通过扫描 `.vue` 文件推断。
- **计数**：从有效登记计算；示意中的名称、组件与差异数不作为已有资源事实。

### 主题差异计算

按当前包内主题及具体模式，与明确标注的基础主题、相同模式比较 Core 已解析的语义键和组件键取值：

1. 从主题绑定与 manifest 读取真实包身份、基础包及主题对应关系；对应关系无法确定时显示未知，不猜测。
2. 对齐键目录，按唯一键统计最终取值不同的项，主题和模式分别计数；常量不计入差异数。
3. 区分作者覆盖与因引用而重新计算的差异，保留 Core provenance；“显式覆盖数”与“最终值差异数”不得混称。
4. 缺键、非法键或解析失败作为诊断展示，不把缺失解释为正常删除 Token 的能力。主题不能改变 Token 语义或键目录。

### 组件扩展识别

- **普通使用**：在某个页面使用 DS 组件、改变文案或选择已有公开 props/variant，不生成原型扩展条目。
- **DS 公开变体**：归属于 DS 基础组件详情；原型采用它可记入 Promotion Mapping，但不重复登记成原型新增变体。
- **原型新增变体**：围绕 DS 公开能力形成有稳定名称、用途及状态的可复用定制，显式声明基础组件和定制内容后进入原型扩展目录。禁止覆盖私有样式。
- **原型自有组件**：显式声明为该原型的可复用组件，提供用途、预览与证据归属；不要求存在 DS 基础组件。原型内部页面、壳、局部 helper 不自动进入目录。
- **通用 DS 扩展**：完成 Contract、Registry 等原子变更后归入 DS 基础目录，原型记录采用关系。

### 原型制作与人工交付检查

新建原型或新增主题、组件扩展时，在 `docs/implementation.md` 的 Promotion Mapping 中记录资源清单，并按[交付检查单](./checklist.md)逐项验收：

| 资源 | 声明与来源 | 预览与证据检查 |
| --- | --- | --- |
| 主题 | 原型绑定的真实包、基础来源、包内主题与模式；无定制时写明沿用基础 | 目录和详情可定位真实定制，Runtime 使用同一包；正式 Evidence 固定包身份、摘要及取值表 |
| 新增变体 | 稳定标识、所属原型、基础 DS 组件、定制内容和实现位置 | 有代表性状态及交互预览；正式 Screen 中 DS 实例仍有业务稳定 inspectId |
| 自有组件 | 稳定标识、所属原型、用途、实现位置和 Evidence 节点边界 | 有预览与状态；正式业务节点满足显式 role、Token Evidence 及完整性要求 |

预览登记只服务 Workbench，不能替代 Runtime 声明、Screen/Variant、Action/Scenario 或正式采集。手册页和探索草稿不能作为 Capture/Handoff 输入。缺少登记、预览或证据验证时，记录缺口与原因，不得宣称链路完成；资源登记能力未实现时也不得伪造字段或声称自动检查已通过。

## 视觉展示

### 主题样板

展示主题时使用紧凑的样板，包含：
- 主题包标识（名称 / 主题 / 模式）
- 主要色彩阶梯
- 字体层级示例
- 按钮、输入框等关键组件在该主题下的样子
- 与基础差异的对照表（如果是原型主题包）

### 组件预览

展示组件时：
- **DS 基础组件**：使用基础主题包渲染，展示所有状态和尺寸
- **原型扩展**：使用该原型的主题包渲染，标注基于哪个 DS 组件

### 手机舞台

全部组件的可视样例，包括类型、尺寸、加载、禁用与其它状态，都在手机容器内展示，以 `component-studio` 为编排参照：

- 使用手机壳容器，不为组件手册引入 iframe；此规则不改变正式 Runtime 画布的 iframe/bridge。
- 小组件用紧凑分组；浮层从设备内触发并限制遮罩、焦点和面板范围；导航和布局组件提供页面上下文。
- 长内容在设备内滚动，保持可读尺寸；不能为放下全部状态而无限缩小预览。
- 设备外仅保留资源导航、必要预览控制与简短用途；说明、Contract 和 Token 绑定按需展开，不另设设备外类型或状态展台。
- 支持浅深模式、触摸、滚动与键盘操作；模式切换保留合理的当前交互状态。

## 导航职责

「设计基础」提供资源目录、基础主题详情、原型主题详情与差异对比；「组件」提供分类基础目录、单组件详情、按原型分组的扩展目录和详情。资源身份由导航与路由明确传递。

设计基础当前使用 `/workbench/foundations/tokens/:category` 与 `/workbench/foundations/themes/:themeId`；组件当前使用 `/workbench/components/:componentId`。本文定义的资源目录与详情路由尚未落地，不作为当前可用入口。

## 草稿与正式实现

展示草稿用于确认编排，正式实现吸收后删除对应展示草稿及专用路由，不保留平行手册；业务原型草稿（例如 yike）不属于此次清理范围。进度统一记录在收敛计划中。

草稿制作规则：
- 草稿目录：`apps/pbwork/src/drafts/{draft-name}/DraftPage.vue`
- 自动注册：通过 `drafts/registry.ts` 的 `import.meta.glob` 自动扫描
- 草稿标签：在 `drafts/registry.ts` 的 `draftLabels` 中声明显示名称
- 草稿共享样板、主题 provider 和样式位于 `drafts/studio-shared/`，正式页面未依赖这些探索实现。
