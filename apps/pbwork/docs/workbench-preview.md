# Workbench 预览工作流

本文规定设计基础与组件预览的作者工作流和人工验收方式。分类、组件 Contract 与主题语义分别由现有手册和 Core 管理；预览不产生正式 Evidence，也不替代 Runtime 声明与采集。

## 当前能力边界

TokenGallery 已有分类、资源范围与浅深模式选择，但尚无包内主题选择；ThemePreview 主要对照基础包浅深颜色。ComponentPlayground 已有主题 Provider、Scenario 和手机壳，但主题选项不含原型包，部分状态展台仍在设备外。双机独立预览、完整手机样板和原型组件扩展登记尚未交付。下列规则是已确认的制作与人工验收依据，不能据此声称这些能力已实现；代码迁移与完成证据统一记录于[平台升级第 6 步](../../../docs/roadmap/pbwork-platform-upgrade.md#第-6-步-设计基础与组件预览迁移)。迁移完成时同步更新本节为实际行为。

## 工作流与职责

1. 先按原型设计工作流确定并批准产品与风格，在 `docs/implementation.md` 中记录主题绑定和 Promotion Mapping。
2. 核对真实主题包及包内主题、模式；区分 DS 原样使用、公开变体使用、原型新增变体与自有组件。
3. 在具体设计基础分类或组件中检查手机预览；需要比较时添加第二台手机，不先建立另一套资源首页或重复整套组件目录。
4. 检查手机内样例、触发、状态与反馈，再核对只读值、来源与差异。登记或预览能力缺失时记录缺口。
5. 正式业务 Screen 另行完成 Evidence、Delivery 与体验检查；手册与草稿预览不能作为 Capture/Handoff 输入。

Workbench 维持稳定的工具界面，主题只影响所属手机的预览。基础 DS 提供默认起点，各原型的获批品牌由各自主题与组件表达；不要求它们采用相同外观。

## 单机与对比

- 保留设计基础分类、组件分类和主要详情路径。默认一台手机；原型增加不自动增加设备或复制目录。
- 每台手机单独选择真实的基础 DS 或原型上下文、包内主题与浅深模式。只有一个选项时显示名称即可；无原型时不显示空的原型选择器。
- 有独立主题的一个原型也可与基础 DS 比较；同一包的多个主题或浅深模式也可比较。重复使用基础包的原型如实标注沿用，不制造自有包或差异。
- 对比按需开启，第一版最多两台手机。新增设备复制当前样例/场景作为起点，再选择比较配置；只改变主题时使用相同内容、逻辑视口与样例结构。
- 手机状态、滚动、浮层 host 与实例标识互相隔离；不做双机操作自动同步。切换包/主题/模式保留仍然有效的交互状态，切换组件重置到该组件默认演示。
- 设备空间不足时由舞台滚动或换行承载，不能无限缩小样例、裁切设备或增加第三个展台。

## 手机边界

所有可视样例放在手机内，包括设计基础样板、组件类型、尺寸、加载、禁用、其它状态、触发按钮及操作反馈。设备外只保留导航、主题与对比控制、简短用途及按需展开的说明、Contract、键值和来源，不另设状态或类型展台。

组件保持真实交互：小组件紧凑分组，导航/布局组件具有页面上下文，长内容在设备内滚动。Overlay 在对应手机内触发，遮罩、面板、焦点与关闭行为属于该设备；关闭后焦点返回自己的触发器。两台手机不能相互接管浮层或状态。

使用现有手机壳，不为手册引入 iframe；正式 Runtime 画布的 iframe/bridge 保持独立。手机边界与正式组件的滚动、Overlay、手势机制分工明确，不复制业务交互机制。预览视口适配不能改写 Core 解析表、摘要或正式采集取值。

## 设计基础样板

保留现有全部分类与信息，不把桌面 Token 表缩小塞入手机。手机承担视觉示意：

| 分类 | 手机内样板 |
| --- | --- |
| 色彩 | 成对前景/背景、页面与多层表面、强调与反馈 |
| 字阶 | 中文标题、正文、辅助文字与数字，使用默认系统字体栈 |
| 间距、尺寸 | 相同内容的留白、控件高度、图标及触控区域 |
| 圆角、边框 | 同一组控件和表面的形态、描边与焦点 |
| 阴影、透明度、材质/效果 | 表面叠放、半透明与玻璃效果 |
| 动效 | 设备内明确触发与可重复播放，尊重减少动态效果偏好 |
| 布局、层级 | 填充、约束、负位移、固定区域、遮罩和浮层关系 |

完整键值与来源仍可查阅。常量单独标明只读、不可被主题覆盖、不可绑定，不把它们当主题差异。完整取值是查阅基础，差异筛选是辅助，不因没有差异就隐藏完整基础能力。

## 主题事实与组件归属

预览读取原型 Registry 的真实 `themePackId`、主题 manifest 和 Core 已解析表，复用 Runtime 的响应式 CSS、主题属性、Token reader 与局部 Vuetify Provider，不另写解析器。包内主题与浅深模式是独立维度；预览选择不修改业务偏好或正式 Capture 默认项。

与基础比较时明确基础包、主题和相同模式；无法确定对应关系时显示未知，不静默猜测。按唯一语义键/组件键统计最终值差异，保留 provenance；作者显式覆盖与继承重算不可混称。缺键、非法组合和解析失败作为诊断，不静默回退成基础包成功预览。

- DS 组件在原型主题下预览，归属仍为 DS；更换文案或选择已有公开 variant/props 不生成原型扩展。
- 原型新增变体显式记录稳定标识、原型归属、基础组件、定制内容、实现及代表性状态预览；不得覆盖 DS 私有样式。
- 原型自有组件显式记录稳定标识、用途、实现、预览及 Evidence 节点边界，不强制存在基础组件。
- 组件扩展以显式登记为依据，不扫描 `.vue`、不按 props 使用推断，不把页面、壳和局部 helper 自动列为组件。没有扩展就不展示空分组。
- 真正扩展在相关组件或原型扩展分组中可定位，复用同一手机舞台；没有对应实现的另一侧显示不适用，不伪造对比组件。

## 原型制作与人工交付检查

在 `docs/implementation.md` 的 Promotion Mapping 记录真实主题绑定、基础来源、包内主题/模式、组件分类与实现位置；无定制时明确沿用基础。预览缺口、登记缺口与正式 Evidence 缺口分别记录。

主题预览与 Runtime 使用同一包；正式 Evidence 仍需固定包身份、摘要与取值表。DS 业务实例提供稳定 `inspectId`；原型自有节点满足显式 role、Token Evidence 和 authored completeness boundary。预览登记只服务 Workbench，不新增 Core 枚举、Case、Catalog 或 Preflight Block。

按[交付检查单](./checklist.md#资源展示人工验收)检查；未实现或未验证的项目如实记为缺口，不把规范同步当成页面完成。
