# Workbench 预览工作流

本文规定设计基础与组件预览的作者工作流和人工验收方式。分类、组件 Contract 与主题语义分别由现有手册和 Core 管理；预览不产生正式 Evidence，也不替代 Runtime 声明与采集。

## 当前能力边界

共享预览边界已接入全部 12 个设计基础分类、浅深主题页及 Registry 的全部 47 个组件入口：默认单机，按需最多双机；每台独立选择主题包、包内主题和浅深模式，独立持有状态与浮层 host，滚动可按需联动。主题包选项读取真实 Prototype Registry 绑定和主题 manifest，按 packId 去重；样例包明确标注仅演示，冷链复用基础包时不再单独列项。切换主题保留有效演示状态，缺包/非法组合/解析失败显示诊断，预览不写业务偏好。

全部入口配套「预览 / 来源」Tab；来源表按分类或组件 Contract 绑定列值，搜索只筛选表格，布局/层级等实现常量单独标明只读、不可覆盖和不可绑定。主题页复用共享手机与来源表，保留主题性格、关键前景对比度和完整取值。组件保留 Icon 矩阵、Tab 自适应/等宽、iOS/Android 转场、业务插槽列表与刷新/分页、Overlay 场景；每台手机单独持有会话，新增对比深拷贝当前可序列化样例与交互值，进行中的模拟请求不作为跨设备操作复制。原型变体/自有组件通过下文显式登记接入；当前正式原型未登记扩展，不显示空分组，能力由隔离测试夹具验证。`theme-studio` 与 `component-studio` 展示草稿保留为探索参照，不替代本工作流，也不进入 Evidence。平台投入范围见[关键升级第 6 步](../../../docs/history/pbwork-platform-upgrade.md#第-6-步-设计基础与组件预览迁移)。

## 工作流与职责

1. 先按原型设计工作流确定并批准产品与风格，在 `docs/implementation.md` 中记录主题绑定和 Promotion Mapping。
2. 核对真实主题包及包内主题、模式；区分 DS 原样使用、公开变体使用、原型新增变体与自有组件。
3. 在具体设计基础分类或组件中检查手机预览；需要比较时添加第二台手机，不先建立另一套资源首页或重复整套组件目录。
4. 检查手机内样例、触发、状态与反馈，再核对逐项样板、只读值与来源。登记或预览能力缺失时记录缺口。
5. 正式业务 Screen 另行完成 Evidence、Delivery 与体验检查；手册与草稿预览不能作为 Capture/Handoff 输入。

Workbench 维持稳定的工具界面，主题只影响所属手机的预览。基础 DS 提供默认起点，各原型的获批品牌由各自主题与组件表达；不要求它们采用相同外观。

## 单机与对比

- 保留设计基础分类、组件分类和主要详情路径。默认一台手机；原型增加不自动增加设备或复制目录。
- 每台手机单独选择真实主题包、包内主题与浅深模式。主题包按 packId 唯一列出，原型归属不作为主题包选项；每个维度只有一个选项时直接显示名称。
- 有独立主题的一个原型也可与基础 DS 比较；同一包的多个主题或浅深模式也可比较。多个原型复用同一包时只显示该包一次；原型仍保留真实 themePackId 绑定，不制造自有包或差异。
- 对比按需开启，第一版最多两台手机。新增设备复制当前样例/场景作为起点，再选择比较配置；只改变主题时使用相同内容、逻辑视口与样例结构。
- 手机状态、浮层 host 与实例标识互相隔离；共同滚动只联动两台手机内容区及对应组件自有列表视口的滚动进度，不同步按钮、场景或浮层操作。切换包/主题/模式保留仍然有效的交互状态，切换组件重置到该组件默认演示。
- 设备空间不足时换行承载，不能无限缩小样例、裁切设备或增加第三个展台。

设备选择以 `pack:{packId}` 身份持久化；旧 `foundation:`、`sample:` 与 `prototype:` 选择按真实注册绑定迁移，仅替换选择身份，保留主题、模式、尺寸、对比与滚动偏好。未知来源和非法主题仍明确报错，不猜测或回退。原型与包的原始关联继续用于来源表归属说明。

## 共享排版

已迁移入口的预览卡片跟随正文居左，卡片顶部提供「预览 / 来源」Tab，下方由共用紧凑设置栏和当前内容页组成。主题包单独一行，主题/模式紧凑并列，固定外部标签不挤入浮动边框；单一选项直接显示名称。通过“单机／对比”切换查看方式，单机手机在舞台内居中，对比时并排并使用 A/B 对应独立设置。

### Tab 与共同滚动

- 「预览」展示手机；「来源」完整列出实际样板、值、定义来源及搜索。设置侧栏只在预览页显示，来源页隐藏整个侧栏并使用卡片完整宽度；表格不再堆叠于手机下方。
- 切换使用约 200ms 的横向翻页位移与淡入淡出，返回方向相反；尊重 `prefers-reduced-motion`。两页保留实例，切换不重建手机，不丢失演示状态、滚动位置与本页搜索；键盘左右箭头切换 Tab 并移动焦点。默认进入预览，不跨资源保存当前 Tab。
- 双机时在手机舞台顶部右侧显示紧凑的「共同滚动」开关，默认开启，偏好跨页面及刷新保留。任一手机滚动都按自身可滚动范围的进度同步另一台；内容高度不同时也可到达相同相对位置。忽略同步写入引发的反馈事件；关闭后独立滚动，重新开启以 A 当前进度对齐。隐藏页不参与滚动联动。
- 缩放手柄采用贴合手机右下角的两条 SVG 斜线，透明背景，悬停/聚焦时强化，32px 热区；保留指针捕获与键盘缩放，无突出的白色方块。

### 容器与显示尺寸

工作台使用独立 localStorage 键 `pbwork:preview-preferences:v1` 共享并保存单机/对比、共同滚动、显示模式、自定义缩放与 A/B 来源/主题/模式。所有接入共享预览的卡片跨页面同步，刷新恢复；不保存组件演示状态、浮层、滚动位置或各页搜索，也不写 Runtime 业务偏好。存储损坏或不可用时仍可操作。

- “适应视区”根据舞台宽高、设备数量和手机外壳占位计算缩放，尽量完整显示手机；“100%”按现有逻辑设备的 CSS 尺寸展示；尺寸说明同时列出逻辑宽高与实际屏幕缩放百分比，适应比例以舞台可用宽度、窗口参考高度及设备留白计算，卡片自身高度不反向限制设备。极窄窗口下 100% 与自定义显示比例以单台设备可用宽度为上限，界面提示自动缩小，避免裁切；两者不修改 Runtime 视口、主题表、字体或采集尺寸。
- 手机设备容器右下角可拖动等比缩放；手柄支持方向键每次增减 5%，范围 25%–150%。外层卡片随设备展示高度自然撑开，由页面承载滚动，不固定舞台高度。容器宽度跟随正文，窄舞台设置区上移，不提供任意改变原型逻辑宽高的入口。
- 手机内容区隐藏可见滚动条，保留滚轮、触摸和键盘滚动并可获得焦点；手机维持固定逻辑视口，长内容仍在手机内滚动。设置区与舞台使用正常文档流，无纵向内部滚动容器；空间不足时双机换行，卡片高度随内容增长。
- 调整尺寸和切换显示模式不重建设备，不丢失演示状态、滚动位置或已打开浮层。双机使用相同逻辑设备与展示比例。

### 来源 Tab、键值表与搜索

设计基础的查值资料集中在「来源」Tab 的“值与来源”表中。按当前分类列出名称、Key、解析值及来源；所有分类均已接入。组件仅列 Contract 绑定的键，不展示整包无关 Token。手机保留完整分类样板与真实组件交互；来源表每项也提供对应值的实际样板：颜色用真实色块，字体逐一以实际字体族、字号、字重、行高、数字特性渲染中英文或数字，并保留参数。间距/尺寸用量尺与内容块，圆角/边框/阴影用真实表面，透明度/滤镜用背景叠层，动效可播放/复位，层级/位移/缩放按实际值示意，资源展示真实资源或明确未配置。所有条目默认完整列出，不以通用占位图代替实际值。相对长度在来源样板容器中示意，参数仍显示原始逻辑值，不改变手机或采集视口。

- 搜索放在表格工具栏，按名称、Key 或说明筛选当前分类；不改变手机样板，保证主题比较内容稳定。空结果明确提示，清空搜索恢复完整表。
- 来源表独立于手机单机/对比与侧栏主题选择。按真实包 manifest 的全部主题生成列，以包/主题去重并标明归属，直接显示主题名，不显示 A/B；当前为默认主题、园色与柑色。来源工具栏独立切换模式并跨页持久化，未知/不支持模式明确诊断，不静默回退。名称/Key 列固定，主题列保留可读宽度，超宽只在表格中横向滚动。样板复用 Core 解析表；不设差异列、“只看差异”或差异统计，相同值也完整展示。
- 来源保留定义包与继承状态，不能把继承后的最终值当作作者显式覆盖；界面不计算差异统计、不展示引用链，Core provenance 数据不变。表内显示真实逻辑值，不用设备缩放或容器视口适配后的 CSS 替换原始解析结果。
- 解析失败、缺包或非法配置明确显示诊断和不可读取；不适用的设备侧明确标注，不伪造有效样板或取值。
- 主题包摘要及其它技术身份按需展开。组件用途与 Contract 说明仍按需折叠，不在设备外重复状态样例。

## 手机边界

手机内保留设计基础完整样板，以及组件类型、尺寸、加载、禁用、其它状态、触发按钮和操作反馈。设备外保留导航、主题与尺寸/对比控制、简短用途、来源 Tab 的逐项基础值样板/参数/定义来源及按需说明、Contract；来源样板只解释键值，不在设备外另造组件状态或业务交互展台。

组件保持真实交互：小组件紧凑分组，导航/布局组件具有页面上下文，长内容在设备内滚动。Overlay 在对应手机内触发，遮罩、面板、焦点与关闭行为属于该设备；关闭后焦点返回自己的触发器。两台手机不能相互接管浮层或状态。

使用现有手机壳，不为手册引入 iframe；正式 Runtime 画布的 iframe/bridge 保持独立。手机边界与正式组件的滚动、Overlay、手势机制分工明确，不复制业务交互机制。预览视口适配不能改写 Core 解析表、摘要或正式采集取值。

## 设计基础样板

保留现有全部分类与信息，不把桌面 Token 表缩小塞入手机。手机承担视觉示意：

| 分类 | 手机内样板 |
| --- | --- |
| 色彩 | 成对前景/背景、页面与多层表面、强调与反馈 |
| 字阶 | 中文标题、正文、辅助文字与数字，使用当前主题实际字体栈 |
| 间距、尺寸 | 相同内容的留白、控件高度、图标及触控区域 |
| 圆角、边框 | 同一组控件和表面的形态、描边与焦点 |
| 阴影、透明度、材质/效果 | 表面叠放、半透明与玻璃效果 |
| 动效 | 设备内明确触发与可重复播放，尊重减少动态效果偏好 |
| 布局、层级 | 填充、约束、负位移、固定区域、遮罩和浮层关系 |

完整键值与来源仍可查阅。常量单独标明只读、不可被主题覆盖、不可绑定，不把它们当主题差异。完整取值和实际样板是查阅基础，相同值也全部列出，不通过差异筛选隐藏条目。

## 主题事实与组件归属

预览读取原型 Registry 的真实 `themePackId`、主题 manifest 和 Core 已解析表，复用 Runtime 的响应式 CSS、主题属性、Token reader 与局部 Vuetify Provider，不另写解析器。包内主题与浅深模式是独立维度；预览选择不修改业务偏好或正式 Capture 默认项。

与基础比较时明确基础包、主题和相同模式；无法确定对应关系时显示未知，不静默猜测。按唯一语义键/组件键并排列出完整样板和值，保留 provenance；作者显式覆盖与继承重算不可混称。缺键、非法组合和解析失败作为诊断，不静默回退成基础包成功预览。

- DS 组件在原型主题下预览，归属仍为 DS；更换文案或选择已有公开 variant/props 不生成原型扩展。
- 原型新增变体显式记录稳定标识、原型归属、基础组件、定制内容、实现及代表性状态预览；不得覆盖 DS 私有样式。
- 原型自有组件显式记录稳定标识、用途、实现、预览及 Evidence 节点边界，不强制存在基础组件。
- 组件扩展以显式登记为依据，不扫描 `.vue`、不按 props 使用推断，不把页面、壳和局部 helper 自动列为组件。没有扩展就不展示空分组。
- 真正扩展在相关组件或原型扩展分组中可定位，复用同一手机舞台；没有对应实现的另一侧显示不适用，不伪造对比组件。

## 显式扩展登记

登记只服务 Workbench 展示，不更改正式 Component Registry、Runtime Contract、Core 或 Evidence。普通 DS props/公开变体使用不需要登记。原型作者在 `src/prototypes/{prototypeId}/preview-resources.ts` 默认导出 `PreviewExtension[]`；类型位于 `src/workbench/preview/extensions/model.ts`。该元数据只由 Workbench 加载，不作为业务 Screen 依赖。

| 字段 | 要求 |
| --- | --- |
| `id`、`label`、`description` | 全局稳定 id、可读名称、定制说明；不得与 DS 或其它扩展重名 |
| `ownerPrototypeId` | 必须是已存在的正式 Prototype Registry id |
| `kind` | `variant` 或 `component` |
| `baseComponentId` | variant 必填且必须是有效 DS 组件；自有组件不填 |
| `implementation` | 相对于 `src/prototypes/` 的所属原型实际 Vue 实现路径 |
| `preview` | 同一原型下明确关联的 Vue 演示入口；不通过扫描实现自动登记 |
| `states` | 非空、id 唯一的代表状态清单（id、label），由预览入口真实演示 |
| `tokenIds` | 来源表的主题键范围，不能登记常量或未知键 |

实现与演示模块放在所属原型 `components/`、`previews/` 下。演示入口接收 `device`、`attach`、`table`、`states`：把本机可复制会话写入 `device.demo.session`，从局部主题表读取值，浮层挂到 `attach`，提供全部登记状态与触发；不嵌套第二层手机壳、不复制滚动/手势/导航机制。预览自身不构成 Evidence。

- variant 在基础组件详情侧栏的「组件实现」中按 A/B 独立选择；归属仍为登记原型，主题选择与组件身份分开。选择 DS 复用基础实现，选择扩展默认切到所属原型绑定的主题包并加载明确关联的预览模块。
- 自有组件只在实际存在时增加“所属原型 · 自有组件”导航分组，沿用 `/workbench/components/{id}`。打开时默认使用所属原型绑定的主题包；自有组件在其它主题包下显示“不适用”，不伪造 DS 对应组件或差异。来源表使用该资源登记的 Token 范围，按主题包对应的真实归属判定适用性；手机的组件实现选择不改变来源列。
- 重复/非法 id、未知 owner/base、缺失或跨原型模块路径、缺失/重复代表状态、未知或重复 Token 均阻断登记。可发现 Vue 模块只用于校验明确路径与加载，不能根据文件或 props 推断资源。
- 当前无正式扩展。隔离夹具覆盖两个虚拟 owner 的变体/自有组件、预览承载、无对侧、非法登记与空导航，不把夹具写入正式 Registry，也不以此声称未来资源已通过 Evidence 验收。

## 原型制作与人工交付检查

在 `docs/implementation.md` 的 Promotion Mapping 记录真实主题绑定、基础来源、包内主题/模式、组件分类与实现位置；无定制时明确沿用基础。预览缺口、登记缺口与正式 Evidence 缺口分别记录。

主题预览与 Runtime 使用同一包；正式 Evidence 仍需固定包身份、摘要与取值表。DS 业务实例提供稳定 `inspectId`；原型自有节点满足显式 role、Token Evidence 和 authored completeness boundary。预览登记只服务 Workbench，不新增 Core 枚举、Case、Catalog 或 Preflight Block。

按[交付检查单](./checklist.md#资源展示人工验收)检查；未实现或未验证的项目如实记为缺口，不把规范同步当成页面完成。

## 全屏与资源工具

LaunchScreen 在一个完整设备内容区内切换状态，不把整屏状态叠成小卡片；静态启动与可交互欢迎明确区分。Icon 的手机样板展示自绘策展集，选择后提供 SVG 或透明 PNG 下载；PNG 可选 1/2/3/4 倍并显示基于当前主题逻辑图标尺寸计算的像素。导出路径和预览使用同一份 SVG 图形定义，导出工具不进入运行时 Icon 的 props。

GlassSurface 为独立材质容器，不决定宿主圆角、业务结构、导航或滚动。玻璃样板把正文放在材质后面，用来看磨砂和清透两档；App Bar 的玻璃态同样盖在页面文字上，正文从标题下方进入栏底，不用色块衬底。手机预览用 zoom 缩放，不用 transform，这样 Chrome 仍能采样栏和卡片后面的文字。降低透明度或不支持背景滤镜时使用实色降级。它是 Web 背景滤镜与光影实现，不声称原生折射。材质层不能包在会截断背景采样的隔离组里。
