# 设计基础与组件预览重构方案

状态：先行草稿评审中。2026-10-17 用户确认先制作“主题与设计基础”和“组件手机舞台”两份草稿；正式推广尚未执行。当前入口与边界见 `src/drafts/DRAFTS_README.md`。下文的正式页面重构批次留待草稿确认后推进。

## 目标

解决主题预览混乱、组件缺乏设备上下文、原型资源无入口、信息层级倒置四大问题,让设计者能直观看到:当前看什么、继承谁、改了什么;组件在手机里的实际效果;原型自己的主题与组件在哪里。

## 核心方向

**"设备舞台优先、说明按需展开"** — 左侧选资源,中间看手机,工具区紧凑选主题和展示内容。主题包详情承担继承说明,组件舞台承担效果展示,避免每页反复解释整套机制。

## 问题定位

### 1. 主题预览 (`TokenGallery.vue`)
- 工具栏堆砌8个控件(外观、深浅、对照、网格/表格...)
- 说明区满屏技术细节(Key/Value/来源/引用链/对比度)
- 主题包关系完全不清楚

### 2. 组件预览 (`ComponentPlayground.vue`)  
- Button 等小组件平铺,类型、加载、禁用散落各处
- Toast/BottomSheet 越出设备边界
- 缺少双机对比、原尺寸查看

### 3. 原型资源无入口
- 第2步已支持原型自有主题包和自有组件
- 但整个 Workbench 没有展示入口

### 4. 信息层级倒置
- CSS 变量、引用链占据常驻空间
- 视觉效果和用途反而被压缩

## 实施计划

分四批推进,每批有明确退出标准。

---

## 第一批:资源模型与主题选择

建立"基础DS/演示包/原型资源"的统一查看模型,压缩主题工具栏。

### 交付

1. **查看范围选择器** (`WorkbenchResourceScope.vue`)
   ```typescript
   type ResourceScope = 
     | { kind: 'foundation' } // 基础 DS
     | { kind: 'sample', packId: string } // 演示包
     | { kind: 'prototype', id: string, packId: string }; // 原型
   ```
   单一选择器替代现有"外观"+"包ID";明确当前看什么。

2. **来源与继承说明** (`ThemeLineage.vue`)
   - 基础DS → [箭头] → 当前原型/演示包
   - 显示覆盖项数量、包ID、主题名
   - 样例包标注"仅演示,不可用于正式原型"

3. **主题工具栏重构**
   - 查看范围(单选) + 包内主题(单选,继承时禁用) + 深浅(toggle)
   - 移除"对照另一套"按钮,改为双机对比模式(第二批)
   - 移除网格/表格切换,Token页统一用网格+分组

4. **Token Gallery 简化**
   - 默认只显示:预览图、名称、取值、来源标签
   - 折叠区:CSS变量、引用链、对比度诊断
   - 移除侧边栏实时选中详情,改为点击打开 drawer

### 退出标准

- TokenGallery 工具栏从8个控件降到3个
- 能清楚回答"现在看谁、继承谁、改了什么"
- 样例包与基础DS一眼可分
- `vue-tsc` 通过

---

## 第二批:组件手机舞台

所有组件预览统一进入手机设备,支持双机对比。

### 交付

1. **统一手机舞台** (`ComponentPlayground.vue` 重构)
   - Button/Chip 等小组件:类型与状态全部进入单机设备
   - Toast/BottomSheet/ActionSheet:浮层限于设备内
   - 导航组件(Tabs/Tabbar):完整页面上下文
   - 双机并排:同模式对比包,或同包对比浅深

2. **舞台工具栏**
   - 对比方式:单机/包对比/模式对比
   - 原尺寸/适应窗口(缩放)
   - 当前展示内容提示(类型、状态、页面上下文)

3. **小组件紧凑分组**
   - Button:类型行(主要/次要/outlined) + 状态行(加载/禁用)
   - 每组内所有变体在同一设备内垂直排列
   - 点击主要按钮可见:默认→加载→完成

4. **浮层真实上下文**
   - 设备内先显示触发按钮("打开 BottomSheet")
   - 点击后面板从底部升起,限于设备边界
   - 支持三档高度、确认、Escape

### 退出标准

- Button 的类型、加载、禁用都在设备内首屏可见
- BottomSheet 打开时不越出设备
- 双机对比时,每台设备完整显示,1280×720 不换行
- Playwright 覆盖:Button 加载/完成,Sheet 打开/三档/确认
- `pnpm test` 通过

---

## 第三批:设计基础页面重做

布局、层级、效果用真实示意替代文字描述。

### 交付

1. **布局示意** (新增 `DesignFoundation/LayoutSpecimen.vue`)
   - 填充比例:容器 + 不同 `layout.fill`/`half` 的色块
   - 负向位移:原位置浅色框 + 偏移后的主色块
   - 容器约束:可拖动宽度条,观察 `dialog-max-width` 实际作用
   - 全部在手机设备内演示

2. **层级示意**
   - 两个平面,前景显示当前 `z-index` 值
   - 背景半透明主色,前景纯表面色

3. **效果示意**
   - 毛玻璃:`surface.treatment` 实际材质背景
   - 阴影:卡片实际投影
   - 动效:时长/缓动的真实小球移动

4. **常量独立页**
   - 与可覆盖的 Token 分开
   - 只读参考,标注"不随主题变化"

### 退出标准

- 布局 `fill`/`half`/`half-negative` 有对应可见示意
- 层级用实际遮挡关系演示
- 效果展示真实材质和动画
- 常量与语义 Token 明确区分

---

## 第四批:原型资源入口与说明收口

补齐原型设计资源展示,并压缩所有页面的技术说明。

### 交付

1. **原型概览新增"设计资源"** (`WorkbenchPrototypeDetail.vue`)
   ```
   - 概述
   - Screen 列表
   + 设计资源 [新增]
     - 主题包:packId, themes, 覆盖项
     - 采用的 DS 变体:哪些公开外观变体
     - 自有组件:列表 + 进入各自预览
   - 采集历史
   ```

2. **自有组件预览入口**
   - 从原型资源进入,标注来源原型
   - 预览逻辑复用 ComponentPlayground 舞台
   - 标注"需在正式 Screen 中满足语义边界"

3. **说明区统一收口**
   - 默认:用途(1句) + 规则(3条) + 关键取值(4项)
   - 折叠:绑定详情、引用链、诊断、技术注释
   - Token 页:移除侧边栏,改为点击打开 drawer
   - 组件页:移除底部表格,改为"语义与令牌"折叠面板

4. **跨页上下文保持**
   - 从 Token 页选了主题包,进入组件页时保持
   - 从原型进入自有组件,保持原型身份

### 退出标准

- 原型概览能直接看到:绑定的主题包、采用的 DS 变体、自有组件列表
- 组件页默认说明≤10行,技术细节全部折叠
- 从 Token 页切到组件页,主题选择不丢失
- `pnpm test` 与 Playwright 全部通过

## 验收与推广边界

### 最终验收

1. 用一个真实原型(如冷链)验证完整链路:
   - Workbench 预览:主题包、自有组件可见
   - Runtime:运行时使用正确主题
   - Preflight:通过语义门禁
   - Capture:主题表、局部节点可采集
   - Handoff:固定主题身份与取值表
   - MCP:可读取主题包和自有组件

2. 视觉回归
   - 1280×720 与 1440×900 桌面
   - 工作台浅/深、内容浅/深
   - 手机边界、双机对比、滚动与焦点

3. 性能
   - Token 页切换主题<300ms
   - 组件页打开 Sheet 不卡顿
   - 双机对比渲染<500ms

### 不做的事

- **不改 DS 组件自身**:Contract、样式、交互机制保持原状
- **不进入 Capture 协议**:草稿探索路由不产生 Evidence
- **不改 Flutter**:Target 同步检查如实报告 pending,不要求清零
- **不做首次 setup**:新用户引导留到后续

### 推广时机

- 四批全部完成
- Button/BottomSheet/布局三个代表页面用户评审通过
- 冷链完整链路验收通过
- 至少一个新原型(如一刻)实际使用自有主题包制作

## 风险与缩减

- 第三批的布局/层级/效果示意成本较高,可先做布局示意,其余推迟
- 第四批的自有组件预览可先做入口列表,详细预览推迟
- 任何批次超期,先暂停与用户确认
