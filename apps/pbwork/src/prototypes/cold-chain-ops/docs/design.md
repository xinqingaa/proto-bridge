# 冷链异常处置台设计基线

> 本文记录现役原型的产品与体验事实，用于纳入统一文档契约；本次迁移不改变现有页面和交互。

## 产品定义

冷链异常处置台面向值守专员和调度主管，用于从异常队列识别高风险运输任务，查看货运与温度证据，完成处置记录并保留需要主管批准的状态。

核心闭环是：发现异常 → 查看货运详情与温度变化 → 选择处置 → 填写结果 → 校验或审批 → 确认完成。

非目标包括完整运输调度、实时设备控制、客户沟通和后台权限管理。

## 信息架构

| 页面 | 唯一职责 |
| --- | --- |
| 异常队列 | 查找、筛选并进入需要处理的异常 |
| 货运详情 | 判断异常影响并选择下一步处置 |
| 处置表单 | 记录原因、动作、结果、检查项和审批信息 |

三个页面组成线性处置流程，不使用根级多 Tab。列表进入详情，详情进入处置；完成或返回时保持明确来源。

## 交互与状态

- 异常队列提供默认、筛选、加载、空和错误状态；筛选必须改变可见记录。
- 货运详情展示摘要、温度变化与事件时间线，并覆盖告警、传感器错误、动作 Sheet 和确认 Dialog。
- 处置表单提供字段校验、主管审批、确认和完成反馈；错误靠近相关输入，Toast 不是唯一成功证据。
- 关键状态由 Variant 或 Scenario 确定性准备，不依赖实时网络或随机数据。

## 视觉方向

界面保持安静、密集和面向操作：风险、身份、温度证据和处置动作拥有清晰顺序；Card 只用于需要边界的业务摘要，列表和表单按 PBWork DS 的层级、间距和 Divider 组织。

颜色只表达品牌、选中、风险、成功和禁用语义。图表服务温度判断，不作装饰。浅色和深色主题使用同一信息结构。

## PBWork 晋级矩阵

| 能力 | 分类 |
| --- | --- |
| App Bar、搜索、筛选、列表、Card、Badge、表单、Sheet、Dialog、Toast | 现有 PBWork DS |
| 温度趋势图、事件时间线中的业务数据表达 | Token 驱动的业务局部 UI |
| Screen、Variant、Action、Scenario 和 required boundary | PBWork Authoring Contract |
| 外部图片或复杂动画 | 当前范围不需要 |

## 验收信号

- 值守人员可从队列进入任一异常并解释风险依据；
- 温度图、时间线和处置入口属于同一货运上下文；
- 表单校验和主管审批状态可独立复现；
- 所有关键状态均可由 Runtime URL、Variant 或 Scenario 确定性到达；
- 正式页面仅使用 PBWork Token、DS 与合规业务局部 UI。
