# 冷链异常处置台设计基线

> 本文记录现役原型的产品与体验事实，用于纳入统一文档契约；本次迁移不改变现有页面和交互。

## 产品定义

冷链异常处置台面向值守专员和调度主管，用于从异常队列识别高风险运输任务，查看货运与温度证据，完成处置记录并保留需要主管批准的状态。

核心闭环是：发现异常 → 查看货运详情与温度变化 → 选择处置 → 填写结果 → 校验或审批 → 确认完成。

非目标包括完整运输调度、实时设备控制、客户沟通和后台权限管理。

## 信息架构

| 页面 | 唯一职责 |
| --- | --- |
| 异常队列 | 查找、筛选并进入需要处理的异常 |
| 货运详情 | 判断异常影响并选择下一步处置 |
| 处置表单 | 记录原因、动作、结果、检查项和审批信息 |

三个页面组成线性处置流程，不使用根级多 Tab。列表进入详情，详情进入处置；完成或返回时保持明确来源。

## 交互与状态

- 异常队列提供默认、筛选、加载、空和错误状态；筛选必须改变可见记录。
- 货运详情展示摘要、温度变化与事件时间线，并覆盖告警、传感器错误、动作 Sheet 和确认 Dialog。
- 处置表单提供字段校验、主管审批、确认和完成反馈；错误靠近相关输入，Toast 不是唯一成功证据。
- 关键状态由 Variant 或 Scenario 确定性准备，不依赖实时网络或随机数据。

## 视觉方向

界面保持安静、密集和面向操作：风险、身份、温度证据和处置动作拥有清晰顺序；Card 只用于需要边界的业务摘要，列表和表单按 PBWork DS 的层级、间距和 Divider 组织。

颜色只表达品牌、选中、风险、成功和禁用语义。图表服务温度判断，不作装饰。浅色和深色主题使用同一信息结构。

## PBWork 晋级矩阵

| 能力 | 分类 |
| --- | --- |
| App Bar、搜索、筛选、列表、Card、Badge、表单、Sheet、Dialog、Toast | 现有 PBWork DS |
| 温度趋势图、事件时间线中的业务数据表达 | Token 驱动的业务局部 UI |
| Screen、Variant、Action、Scenario 和 required boundary | PBWork Authoring Contract |
| 外部图片或复杂动画 | 当前范围不需要 |

## 验收信号

- 值守人员可从队列进入任一异常并解释风险依据；
- 温度图、时间线和处置入口属于同一货运上下文；
- 表单校验和主管审批状态可独立复现；
- 所有关键状态均可由 Runtime URL、Variant 或 Scenario 确定性到达；
- 正式页面仅使用 PBWork Token、DS 与合规业务局部 UI。

## 页面设计增量：值守视图层级与内容边界

本增量在既有产品定义和线性处置流程内收敛页面层级，不改变异常、货运或处置对象。

### 异常队列

- 唯一职责：让值守人员先按严重度定位异常，再进入具体运输详情。
- 首屏阅读顺序：当前风险摘要 → 搜索 → 严重度视图 → 异常列表。
- 严重度视图是同一异常集合的主要内容分区，全部、严重、警告和关注拥有明确的当前视图；摘要区的“仅看严重异常”只作为进入严重视图的快捷入口。
- 关键状态：默认全部、严重/警告/关注筛选、加载、无结果、数据错误。
- 可观察信号：切换严重度后当前视图和列表集合同步变化；列表行进入对应货运详情；筛选和搜索无结果时给出下一步提示。

### 货运详情

- 唯一职责：在同一货运上下文中解释风险依据，并选择下一步处置动作。
- 首屏阅读顺序：风险告警 → 运输概览 → 箱温趋势 → 运输事件 → 开始处置。
- Card 的标题和说明属于内容结构，业务证据在内容区内保持统一边界，不依赖 surface 本身表达层级。
- 关键状态：正常运输、持续超温、传感器离线、处置操作打开、确认接手打开。
- 可观察信号：温度图、时间线、风险告警和货运身份指向同一票运输；Sheet 与 Dialog 的结果可复现。

### 处置表单

- 唯一职责：记录异常判断、现场确认、后续安排和主管审批，并提交处置结果。
- 首屏阅读顺序：货运上下文 → 处置判断 → 现场确认 → 后续安排 → 主管审批 → 审核并提交。
- 每个表单分组拥有清晰标题、说明和字段边界；错误靠近相关输入，确认和成功反馈保持独立可见。
- 关键状态：默认、字段校验错误、缺少主管审批、提交确认、提交成功。
- 可观察信号：不完整记录被阻断；缺少主管时只提示审批缺失；完整记录进入确认并在提交后显示完成反馈。

### 共享视觉语法

- 以冷链值守台为视觉命题：背景安静、信息密集，冰蓝承担主操作和正常状态，警告黄与严重红只表达风险。
- 页面局部 Card 采用“标题区 + 内容区”结构，列表行、图表和表单分组使用统一的 Token 间距和边界。
- 目标视口包含主要 Runtime 视口和窄屏；文字、路线、时间线和指标允许收缩或换行，键盘 focus 与 reduced motion 遵循 PBWork DS。
