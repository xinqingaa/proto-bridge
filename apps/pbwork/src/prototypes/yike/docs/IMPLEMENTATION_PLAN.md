# 一刻原型执行方案

> 执行授权：2026-10-18，按现有批准草稿和设计基线继续制作。平台升级已由用户确认完成。本文件定义如何执行；实时状态和检查证据只写入 [implementation.md](./implementation.md)。

## 主线与范围

按「先从草稿提取主题与组件 → 用验证过的资源制作页面 → 每完成一页与草稿对比」推进。先做全局盘点，主题与 DS 适配按页面依赖推进；原型专属内容直接在页面上下文制作与对比，不以建成独立组件库或完成所有资源预览作为页面开工条件。无需等所有页面完成才验收，也不反复开启视觉采访。

输入是 [design.md](./design.md) 的批准契约与 `drafts/yike/styles/` 的三套完整风格，保留机械、水位、日影及浅深两种模式，字体统一默认系统字族。首次为零历史和四个预置习惯；草稿的有数据状态另用确定性 fixture 准备。

最终范围为启动、专注、打卡、习惯详情、新建/编辑习惯、回顾、设置七个业务页面，以及共享会话/存储、Runtime 状态、Evidence 和整原型定稿。Flutter Target 还原不在本轮范围。

平台计划不再作为一刻的待办。实际遇到平台能力缺陷时，在唯一问题表记录最小复现与影响；必要的通用修复另归平台权威手册，不新建一套一刻升级计划。

## 当前阶段顺序（2026-10-19 用户确认）

先完成设计与资源盘点 A，再收口主题与组件适配 B，之后继续共享业务基础 C、七页实现 D 和整体交付 E。已有 C/D 成果保留；当前不扩展页面流程，不用页面制作替代资源缺口核对。

A 的退出条件是七页依赖、主题值/资产、DS归属与代表状态都有明确去向，未解决项具名；B 的退出条件是这些资源足以支撑七页、关键视觉/行为风险已验证，必要公共扩展已同步。资源可用现有公共预览或最小上下文检查，不新建独立业务组件库，不要求为每个本地资源添加独立展台。完整业务数据、逐页草稿对照与正式 Evidence 仍在 C/D/E 验收。

本节调整实施优先级；下方 G1–G5 保留跨资源/页面的范围及同步约束，不能把 G4 页面接入提前作为 A/B 完成依据。

### 玻璃范围收敛（2026-10-19）

## 主题与归位确认清单

本清单落实用户批准的详细范围；实施状态仅在implementation.md维护。

- 三主题共用页面、状态、导航与DS实现，各保留浅深模式。机械保留柿色、刻度与孔；水位保留苔绿、水体与滴；日影保留靛蓝、纸面软影与印。主题参数表达字阶、圆角、染色与高光，不复制三套页面。
- 明确玻璃区域：根导航、局部切换、设置分组、习惯卡行、详情概况、回顾总结、当天记录和共享面板。主按钮先保证强调与对比；表盘、水体、纸面和图表标记保留签名材质。避免内部逐层叠玻璃，保留实色降级。
- DS归位范围：Tabbar、SegmentedControl、Button、IconButton、GroupedList/ListCell、Metric、TextField/Stepper/Switch、DurationPicker、共享Sheet/Confirm/Toast、MonthCalendar、Heatmap。具体归属及缺口见resources.md。
- 原型本地范围：三表盘、打孔卡行与标记、轮次计圈、业务表单、三形态周图、面板业务内容以及共享业务数据。不为这些内容新增Workbench独立组件条目。
- 下一实施依赖：文档纠偏与控件归位 → 共享业务状态/壳 → 七页逐页接入、草稿对照 → 六组合与整体旅程验证。已有成果继续使用，不等待独立资源展台完成。

## 文档和状态规则

- 产品决定仅在 design.md；资源归属和视觉规格仅在 resources.md；当前进度、问题及验收证据仅在 implementation.md。
- `theme/` 只放主题代码与资产，组件与页面目录不另起计划。仓库 roadmap 只记录平台投入，不维护一刻入口、计划或进度。
- 已存在的代码逐项接续，不删除重做，不因文件或测试存在就算完成。
- 工作单元使用「待制作 / 制作中 / 待验收 / 已验收 / 阻塞」；已验收必须附检查结果。资源、页面、体验和 Capture 分别记事实。
- 草稿批准不是正式实现验收；预览可加载不是组件验收；静态检查通过不是 Runtime/Capture 通过。

## B：主题与组件适配，服务页面落地

先建立 B1 的主题基础，再按页面需要完成 B2/B3；已有成果直接接续，不继续搭建独立业务组件库。DS 变体在对应组件中预览，专属图形和组合内容在原型页面中验证。

| 单元 | 工作内容 | 产出与退出标准 |
| --- | --- | --- |
| B1 主题 | 完成三套主题的六张解析表；逐项检查显式覆盖/继承；记录对比度修正和与草稿的差异 | Core 全组合解析和对比度通过；字体族不变；Workbench/Runtime 同包，资源预览中核对实际使用的 DS 控件 |
| B2 DS 适配与专属内容 | Tabbar、顶部切换、按钮等优先 DS 变体；表盘及确无类似 DS 的内容保留在原型内；具体承接见 resources.md | DS 变体在对应组件预览；专属内容直接在原型中对照，Token/Flex、状态与六种主题组合按实际使用验证；不要求独立资源登记 |
| B3 组合资源 | 用真实公共 props/slots 组合输入、设置行、按钮、确认、撤销提示和编辑面板 | 确认焦点/关闭/滚动复用共享机制；组合内容能在原型上下文触发与复位，差异记录清楚；不要求独立业务组件预览 |

资源验收检查颜色、字阶、比例与材质，不只看换色。草稿签名：机械扇面读真实 60 分钟刻度，水位数字半浸反色，日影软影在深色为光晕。零值、整小时、超过一小时、暂停、休息和完成不能误读。

样式值只能来自当前合法主题键/实现常量，SVG 使用受控 artwork。现有键无法表达时先写明具体缺口及合法承接方式，不随意添加业务键或绕过 Token 门禁。DS 的现有绑定不因业务需要换绑；与批准风格冲突的主操作、导航、图形按资源映射处理。

## D：逐页闭环

顺序体现依赖。启动与设置先建立主题应用链路；专注形成真实记录，随后打卡管理和回顾接入同一数据。每行完成「制作 → 对比 → 修正 → 复验 → 更新唯一记录」后才向下一行推进。

| 单元 | 页面 | 制作与关键状态 | 独立证据节点/对比焦点 |
| --- | --- | --- | --- |
| D1 | 启动 | 三套品牌静帧；冷启动、已保存主题、减少动态效果、恢复/损坏分流 | 品牌、产品名、入口完成；不增加人为等待，不返回启动页 |
| D2 | 设置 | 表盘/模式、四种配置选择、提示音、重置确认、保存失败 | 表盘预览组、模式、配置组、危险入口与确认；配置只作用后续阶段 |
| D3 | 专注 | 番茄待开始/运行/暂停/短长休/完成；正计时含圈；倒计时设置/到点/追加；放弃/取消/切模式确认、恢复和保存失败 | 日期与真实统计、局部模式、表盘/数字、轮次/圈、主次操作、确认与恢复面板、根导航 |
| D4 | 打卡 | 初始四习惯、部分/全部完成、空、仅归档、撤销/换日/保存失败 | 标题/完成数、新建、共用星期表头、稳定 key 的行/孔位/今日按钮、撤销、归档入口、根导航 |
| D5 | 习惯详情 | 每日/每周、零/有记录、创建前与未来、归档/恢复、删除确认、对象不存在 | 标题、概况、周目标、年度图、操作、危险确认 |
| D6 | 新建/编辑 | 默认空表单/已有值、六图标、每日/每周次数、提醒开关/时间、校验/保存/取消 | 名称/就近错误、选择组、次数、提醒、保存、关闭；取消不污染原值 |
| D7 | 回顾 | 周/月、周期翻页、选中/收起日明细、全空/仅打卡/仅专注、跨日与追加 | 范围、真实总结、每日图形/日历、类型/日明细、未来禁用、根导航 |

28 个草稿状态是视觉基线，不是正式状态上限。设计契约新增的业务边界需补 Variant；复用状态通过 fixture 表达，不把「主题」注册成 Variant。Case 数量以真实 manifest/Selection 为准，取消旧计划的 40–70 个估算与单模式假设。

## 每一页的对比和退出标准

1. 准备相同主题、模式、逻辑视口 `390 × 844`、状态和 fixture。首次默认态使用真实零历史；对比草稿有数据画面时明确使用对应 fixture。
2. 获取草稿手机内容与正式 Runtime 的真实截图；排除工作台外壳和草稿缩放。记录截图/可复现入口、差异、修改和复验结果。
3. 对比结构/阅读顺序、组件形状、Token/材质/比例、状态、交互五项。数据不同须区分真实业务口径与视觉偏差，不为匹配草稿造历史。
4. 在正式实现上应用 frontend-design 的体验检查。普通页默认 Quick；共享视觉语法、核心计时/打卡、数据图形和复杂 Overlay 使用 Focused，选择 3–5 张风险截图。机械执行全主题×全状态截图矩阵不作为每次迭代要求。
5. 检查显式 required boundary、节点唯一/可见/非零 bbox、合法 role 与完整 Token bindings。业务 DS 实例用稳定 inspectId，关键动作有 Action/Scenario/Checkpoint，prepare/readiness/reset 可重复。
6. 执行受影响的 typecheck、authoring lint、注册/布局/Token/行为检查和 Runtime 冒烟，记录结果；本页的 Delivery 与体验均通过才记已验收。

对比记录模板写入 implementation.md 的页面行下，使用：`页面/Variant/fixture → 主题/模式/视口 → 草稿与正式截图 → 五项差异 → 修正 → 验证命令/结果 → Experience 等级 → 遗留`。实现前不伪填通过。

## E：整体验证与正式交付

- E1 串起完整旅程：开始/暂停/继续/休息、后台与重开、计圈、倒计时多次追加、打卡撤销、新建/编辑/归档/恢复/删除、主题/模式与运行中改配置、损坏与重置。
- E2 六种主题组合的主题探针、窄屏、减少动态效果及最终批次体验审阅；按 PBWork checklist 查 Token、Flex、Evidence、共享机制与导航。产品状态模型测试按真正风险编写，不为每页复制 Core fixture/e2e。
- E3 运行 `pnpm --filter @proto-bridge/pbwork typecheck`、PBWork tests、`pnpm test:e2e:runtime`、`pnpm docs:verify`、`pnpm ds:target-sync:verify`；完整交付批次运行 `pnpm verify`。失败明确范围，不能改文档声称通过。
- E4 通过生命周期工作流「待确定 → 已定稿」触发整原型 Capture。检查 Selection、Case、Coverage、Issue，固定主题包/摘要/取值表与声明时钟；Handoff/Delivery 绑定，MCP 按固定引用回读。采集未完成或存在 Block 不能宣称 final。
- E5 implementation.md 记录可复核的检查结果与固定产物引用；不提交 `.proto-bridge/store/`、`output/` 或 Target 构建产物。

## 调整与缩减

发现产品契约冲突时回到 design.md 闭合具体增量。技术问题先在唯一问题表定位到当前工作单元，修复影响该单元的最小范围。可以延后 Flutter 还原和非必要动效精修；不能砍掉三套主题、真实状态共享、核心交互、逐页对比、Evidence 和正式定稿来换取完成声明。
