# 一刻

一刻是本机使用的专注与习惯工具，包含番茄钟、正计时、倒计时、习惯打卡和周月回顾。

## 文档职责

| 文档 | 负责什么 |
| --- | --- |
| [产品说明](product.md) | 产品定位、范围、页面职责、导航与核心使用路径 |
| [逻辑与交互](logic-and-interactions.md) | 业务对象、数据流转、状态机、保存恢复、统计及异常反馈 |
| [UI 与动效设计](ui-design.md) | 页面结构、滚动边界、主题图形、资源复用、动效及可访问性 |
| [已知缺口](known-gaps.md) | 原型实现偏差、目标准备情况和未验证边界 |

先读产品说明，再按任务阅读逻辑与 UI 文档，并核对已知缺口。四份文档按职责展开同一份产品基线，不用计划或实现现状静默改变要求。[design.md](design.md) 保留既有已批准的产品原文，本次未改动；新增说明不自动批准新的业务行为。

## 维护与交付

本目录维护一刻原型的产品说明、逻辑与交互、UI 与动效说明及已知实现限制。`design.md` 保留已批准的产品基线；当前实现的偏差以 [known-gaps.md](known-gaps.md) 为准。

独立 Target 读取自己的本地 docs。`pnpm pb:new:flutter <name> --prototype yike` 按 `target-docs.json` 导入产品、逻辑与 UI 文档；批准基线与原型缺口分别保留在 Target 的 `docs/prototype/`，不覆盖 Target 自己的缺口与工程规范。文件清单、链接校验和来源记录见 [Flutter Target 脚手架](../../../../../../docs/guides/flutter-target-scaffold.md#原型文档导入)。

页面、截图和交互证据通过固定 Handoff/MCP 读取；产品文档通过本地文件读取，不登记文档 Catalog 或文档 Snapshot。文档副本不自动绑定 Handoff 版本，文档要求与固定观测冲突时保留双方来源。动效说明表达设计意图，静态采集不证明正常运动过程。

一刻的实现交付完整保留全部业务状态与交互终态，并按已声明的实例用法补采表盘、日历强度、设置选中态、字体排版和弹层等外观样本。默认交付不表示每种主题的全部状态均实拍；具体范围、规则及固定来源以 Handoff 的覆盖信息为准。需要逐外观视觉核查时使用“全部外观检查”。采集合同见 [ProtoBridge 采集链路](../../../../../../docs/architecture/capture-pipeline.md)。
