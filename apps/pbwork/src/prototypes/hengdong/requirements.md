# 恒动产品设计

> 状态：已确认并进入重构实现，本文作为产品与体验验收基线。
>
> 本文是产品与体验的唯一设计基线。它描述为什么做、用户如何完成任务，以及界面如何组织；路由、测试与 Evidence 等实现细节另行记录。

## 一句话定义

恒动是一款面向健身新手与重启者的低压力训练执行器：让用户在 10 秒内知道今天做什么，用一小段可完成的训练建立连续感。

它不是课程内容平台，也不是精细运动数据工具。它优先解决三个连续问题：难开始、执行中容易退出、完成后感受不到积累。

## 本次重构要解决什么

当前原型有功能，但没有形成清晰的产品主线：四个底部入口职责交叠，页面内又叠加主标签；部分控件只改变选中样式，不改变内容；训练、日历和记录之间缺少可验证的状态连续性；页面普遍采用白色 Card 堆叠，视觉焦点与信息层级不清楚；根页面顶部也没有稳定处理安全区域。

本次重构采用以下核心决定：

- 底部导航由四项压缩为三项：**今天、计划、进度**。
- “我的”不再占据一级入口；目标、提醒、主题与退出统一进入设置页。
- “记录”和“统计”合并为“进度”，用时间范围驱动数据与记录，不再并列两个假主标签。
- “我的计划 / 推荐”不再作为页面内一级标签；当前计划是固定首区，推荐内容通过真实筛选浏览。
- 主闭环固定为：**今天获得建议 → 开始或快速记录 → 完成 → 看到进度变化 → 回到下一次行动**。
- 视觉从“Card 容器集合”改为“编辑式信息编排”：字体、留白、分割线、背景层次和局部强调承担主要结构。

## 用户与使用情境

### 核心用户

- 刚开始锻炼，尚未形成固定训练方式的人；
- 停练一段时间，希望低门槛重新开始的人；
- 不追求专业训练分析，只想保持每周活动节奏的人。

### 典型情境

- 早晨或下班后打开应用，希望马上知道今天做什么；
- 时间有限，只能完成 5–20 分钟活动；
- 正式训练做不完，仍希望保留一次真实活动记录；
- 一周结束时，希望看见自己是否比“完全没动”更进一步。

### 用户阻力

- 选择成本高：不知道选什么、做多久、做到什么程度；
- 开始成本高：打开应用后仍要浏览多个模块；
- 中断成本高：退出后不知道进度是否保留；
- 反馈过弱或过度惩罚：只有数据，没有“我确实在持续”的感受；断签后又容易放弃。

## 产品承诺与设计原则

### 核心承诺

用户每次打开恒动，都能明确看见一个最值得做的下一步；完成后，结果会立即进入可见的连续记录。

### 设计原则

1. **先行动，再管理**：今天页首先给出可执行动作，不先要求用户整理计划或数据。
2. **一次只强调一个决定**：每个页面有一个主导任务，次要能力通过弱层级入口提供。
3. **完成比完美重要**：允许快速记录和提前结束，不用失败式语言惩罚用户。
4. **状态必须连续**：训练、记录、计划和进度之间使用同一份本地数据；操作后的变化必须可见。
5. **克制但不空洞**：减少装饰容器，用信息层级、节奏和语义颜色建立设计感。

### 非目标

- 不接入服务端、社交、排行榜、教练或社区；
- 不提供真实支付、会员、课程视频和器械连接；
- 不做营养、体重、睡眠等综合健康管理；
- 不追求专业训练负荷、心率区间或医疗建议；
- 不用大量徽章、连续天数警告或羞耻式文案制造压力。

## 核心对象与状态

| 对象     | 作用                 | 关键状态                                         |
| -------- | -------------------- | ------------------------------------------------ |
| 用户     | 保存轻量身份与偏好   | 未登录、已登录                                   |
| 计划     | 组织一组可执行动作   | 推荐、自建；未采用、当前使用、已停用             |
| 训练会话 | 表示一次正式训练过程 | 未开始、进行中、已暂停、已完成、提前结束、已放弃 |
| 活动记录 | 形成进度的事实来源   | 正式训练、快速记录；可查看、可删除               |
| 每周目标 | 给出温和的节奏参照   | 目标次数、已完成次数                             |
| 提醒偏好 | 决定是否展示提醒设置 | 关闭、开启并设定时间                             |

对象关系：一个用户只有一个当前计划；计划包含多个动作；完成或提前保存训练会话后生成一条活动记录；快速记录不依赖计划，也会生成活动记录；进度页完全由活动记录计算。

## 信息架构

### 根导航

底部导航始终只有三项，并只出现在三个根页面。

| 根页面 | 唯一职责               | 主要内容                                   | 明确不承载                       |
| ------ | ---------------------- | ------------------------------------------ | -------------------------------- |
| 今天   | 决定并完成下一次行动   | 今日建议、继续训练、快速记录、最近一次结果 | 完整计划管理、历史分析、账户表单 |
| 计划   | 选择与调整“以后做什么” | 当前计划、推荐计划、筛选、新建与编辑入口   | 今日执行状态、历史趋势           |
| 进度   | 回看“已经做了什么”     | 周/月摘要、活动节奏、日历、记录列表        | 计划编辑、训练执行               |

设置是全局工具，不是一级目的地。从今天页右上角进入；保存或返回后回到原页面。计划页右上角用于新建计划，进度页右上角用于筛选，因此不会出现多个同权全局入口。

### 页面地图

共 9 个页面，外加 5 类任务型浮层。

| 层级 | 页面       | 页面存在的理由                   | 主要离开方式                       |
| ---- | ---------- | -------------------------------- | ---------------------------------- |
| 入口 | 登录       | 恢复本地身份并进入应用           | 登录到今天；进入注册               |
| 入口 | 注册       | 建立本地身份和初始目标           | 注册成功到今天；返回登录           |
| 根级 | 今天       | 提供最明确的下一步               | 底部导航；进入训练、计划详情或设置 |
| 根级 | 计划       | 管理当前与候选计划               | 底部导航；进入计划详情             |
| 根级 | 进度       | 查看周期结果和历史记录           | 底部导航；打开记录详情浮层         |
| 二级 | 计划详情   | 判断是否采用、开始或编辑某个计划 | 返回来源；开始训练；打开编辑流程   |
| 二级 | 训练执行   | 专注完成一次训练                 | 完成到训练总结；退出回到来源       |
| 二级 | 训练总结   | 确认本次结果并形成反馈           | 保存后回到今天                     |
| 二级 | 设置与目标 | 调整周目标、提醒、主题和账户     | 保存或返回到今天                   |

任务型浮层：

- **快速记录流程**：活动类型 → 时长与感受 → 确认；
- **计划编辑流程**：基本目标 → 频率与时长 → 动作配置 → 保存；
- **记录详情底部面板**：展示单条记录与删除入口；
- **进度筛选底部面板**：筛选活动类型，不承担时间范围切换；
- **确认对话框**：用于退出训练、删除记录等不可直接恢复的操作。

### 导航约束

- 底部“今天 / 计划 / 进度”是唯一根级导航。同一根页面不再叠加另一组一级 Tab，也不出现第三级 Tab。
- 页面层级不通过增加 Tab 表达。计划详情、训练执行和设置使用进入/返回关系；没有必要的“二级 Tab”本身不是缺失。
- 计划页只保留一个局部**筛选条**，用于真实改变推荐列表；它不是导航，“当前计划”也不参与筛选。
- 进度页只保留“本周 / 本月”一个局部**视图切换**，它会同时更新摘要、图表、日历范围和记录列表。
- 每个导航项、视图切换和筛选都必须改变可见内容或数据结果。只改变选中样式的控件不进入原型。
- 二级页不显示底部导航，避免训练或编辑任务被根导航打断。
- 返回必须回到进入前的页面和滚动/选择状态，不默认跳回今天。

## 关键用户旅程

### 1. 首次进入

1. 用户在登录页输入本地账号，或进入注册。
2. 注册只收集昵称、账号和密码，并设置一个默认每周目标；所有数据仅写入当前浏览器。
3. 校验错误显示在对应字段附近；提交按钮在必填项无效时禁用。
4. 成功后进入今天页，直接看到一项可开始的短训练，不再追加冗长引导。

原型会预置一个可用账号与少量历史记录，方便直接体验；注册的新身份也拥有一套最小初始计划。

### 2. 今天完成正式训练

1. 今天页首屏显示当前日期、简短状态判断和唯一主操作“开始 15 分钟训练”。
2. 若存在未结束会话，首屏主操作改为“继续训练”，并显示已完成动作数；新训练入口降为次操作。
3. 进入训练后，页面只强调当前动作、剩余时间/次数和“完成当前动作”。动作完成后自动推进，并用短动效确认进度。
4. 暂停会冻结计时；离开应用或返回后，会话状态写入本地并可继续。
5. 用户可提前结束。确认框提供“保存已完成部分”“继续训练”“放弃本次”三个语义清楚的结果。
6. 完成最后一个动作或保存已完成部分后进入训练总结，选择体感并确认保存。
7. 保存生成一条记录，更新今天页与进度页，并明确显示“本周 2/3 次”等结果。

### 3. 快速记录一次活动

1. 用户在今天页点击“记录其他活动”。
2. 流程中选择步行、拉伸或自由训练，再选择/输入时长和体感。
3. 确认前显示即将保存的摘要；保存后关闭流程并在今天页显示新记录。
4. 记录立即计入本周进度。若取消，已输入内容只在本次浮层生命周期内保留。

### 4. 采用或编辑计划

1. 计划页顶部直接展示当前计划及本周完成情况，不需要切换“我的计划”。
2. 推荐区域默认展示全部计划；目标筛选会真实改变列表和结果数量。
3. 进入计划详情后可以“设为当前计划”或“开始一次”。当前计划只显示“开始训练”和“编辑计划”。
4. 设为当前计划后，计划页与今天页的建议同步变化，并提供一次可撤销提示。
5. 编辑流程的每一步都有真实字段与校验；保存后回到详情页并显示新内容。

### 5. 查看进度与记录

1. 进度页默认展示本周完成次数、总时长与活动节奏。
2. 切换“本月”时，所有摘要、图表、日历选区和记录列表使用同一时间范围，不能只改变标签样式。
3. 点击日历日期会选中该日，并将记录列表收窄到该日；再次点击或清除选择恢复当前范围。
4. 点击记录打开底部详情面板。删除前必须确认；删除后摘要、图表、日历标记和列表同时更新。
5. 无记录时保留时间范围选择，并给出“从今天开始”的返回入口，而不是显示空白卡片。

## 页面级交互与状态

### 三个根页面的共同框架

- 三个根页面只统一安全区域契约和底部导航，不统一顶部组件。安全区域是布局约束，不是要求每页都添加 App Bar。
- 今天页使用顶部安全留白加轻量工具行；计划页和进度页因需要稳定标题与页面操作，使用紧凑 App Bar。
- 无论采用哪种顶部形态，标题、工具和首个内容焦点都必须从顶部安全区下缘开始，不能与系统状态区域重叠。
- 根页面底部为三项导航，并吸收底部安全区；可滚动内容预留足够尾部空间，不被导航遮挡。
- 切换根导航保持各页滚动位置、筛选与时间范围。
- 页面首屏只能有一个最高强调的动作或信息焦点。

### 今天

- 默认状态：短训练建议为焦点；快速记录是紧邻主操作的文字/次按钮。
- 进行中状态：焦点替换为会话恢复，不同时并列两个主按钮。
- 已完成状态：显示当日完成反馈与下一次轻量建议，避免重复催促。
- 无当前计划：提供“选择一个计划”主操作，同时仍允许快速记录。
- 最近记录：采用两行信息条和分割线，不使用完整 Card；点击进入记录详情面板。

### 计划

- 顶部“当前计划”是唯一高强调区域，可直接开始训练。
- 推荐计划使用标题、元信息和分割线形成列表；只有被选中的目标筛选项使用强调色。
- 搜索不是本轮核心能力，不显示不可兑现的搜索框。
- 无自建计划不等于空页面，仍展示当前计划和推荐内容。
- 新建计划入口始终可见；保存失败时停留在当前步骤并显示字段错误。

### 进度

- 周/月分段控件紧邻页面标题后的摘要区域，表达它会影响整个页面。
- 最高视觉焦点是一组主数字与趋势，不把每个指标分装成独立 Card。
- 活动图表与日历用于不同问题：图表回答“节奏怎样”，日历回答“哪天做了什么”。
- 日期选择、活动筛选和范围切换的结果同时反映在记录列表标题中。
- 删除记录后提供短时撤销；撤销后恢复所有派生数据。

### 训练执行

- 进入时自动开始当前动作计时；计次动作不显示伪计时器。
- 主操作固定在易触达区域；暂停、上一步和退出保持次级。
- 暂停时主操作改为“继续”，页面状态明显变暗但内容仍可阅读。
- 全部完成后不在原页用 Toast 代替结果页，必须进入训练总结。
- 屏幕锁定、刷新或意外离开后，重新进入能恢复最近会话。

### 训练总结

- 展示完成时长、动作数与本周目标变化；提前结束时使用“已完成”而非“失败”。
- 体感选择为单选并直接可见；备注为可选项。
- 保存成功后回到今天，并在首屏看到刚刚产生的结果。

### 设置与目标

- 周目标、提醒时间和主题按平面表单分区，以分割线组织，不套多层 Card。
- 主题切换立即预览并写入本地；其他设置通过底部保存操作提交。
- 退出登录需要确认，但不会清除本地历史；注册身份数据仍可再次登录。

## 状态与反馈基线

| 状态     | 体验要求                                               |
| -------- | ------------------------------------------------------ |
| 加载     | 本地数据读取只使用轻量骨架或短暂占位，不闪烁完整空页面 |
| 空数据   | 解释当前为何为空，并给出与该页面职责一致的下一步       |
| 校验错误 | 靠近字段说明原因；修正后即时消失                       |
| 禁用     | 同时通过样式和不可点击行为表达，并保留可理解的禁用原因 |
| 保存成功 | 内容本身立即变化；Toast 只作补充，不作为唯一证据       |
| 删除     | 二次确认，删除后短时可撤销，所有派生数据同步变化       |
| 中断     | 正式训练自动保存进行中状态；再次进入优先恢复           |
| 离线     | 产品默认离线可用，不展示网络错误或同步状态             |

## 视觉方向：安静的运动感

### 视觉命题

像一份清醒、克制的私人训练手账：有行动张力，但不使用高噪声竞技视觉；让用户先看见“下一步”和“已经完成”，再看见辅助数据。

### 表面与层级策略

- 页面背景使用基础 Surface；大部分内容直接排版在页面上。
- Card 只用于三类需要明确边界的内容：可恢复的训练会话、当前计划的强摘要、完成后的结果反馈。
- 普通列表、设置项、历史记录和说明区使用字体层级、间距与 Divider，不套 Card。
- 浮层使用设计系统的 Sheet、FlowSheet 和 Dialog 语义；不自行模拟悬浮白框。
- 明暗主题使用同一语义结构，不以写死白色、黑色或阴影建立层级。

### 字体与节奏

- 页面级主数字与训练动作使用 Display/Title Token，形成明确焦点。
- 页面标题、区块标题、正文、辅助信息至少形成四级稳定层次。
- 数字与单位分级：数字更强，单位退后；不把多个指标做成相同尺寸的方块。
- 根页面采用舒展首屏和紧凑列表的节奏对比；区块之间用大间距，区块内部用小间距。
- 训练执行页减少文字密度，进度页提高信息密度，但沿用相同字体与间距 Token。

### 颜色与强调

- 品牌主色用于选中状态、进度与关键路径，不大面积铺满所有容器。
- 主操作可使用高对比的品牌实色；同屏只有一个最高强调按钮。
- 成功色只用于已完成和正向变化；警示色只用于退出、删除和真实风险。
- 次要信息使用语义文本 Token；禁止用任意灰值自行制造层级。
- 连续性不只依赖颜色，还要有文本、图标或形状差异。

### 图形、图表与动效

- 图标用于识别操作，不作为大面积装饰；统一使用现有图标系统。
- 周节奏图与日历是仅有的两类业务可视化。若设计系统没有等价组件，可保留为 Token 驱动的业务组件，但不设“自定义组件数量”指标。
- 图表必须可读、有选中状态，并与记录数据同源。
- 动效只用于动作推进、完成确认、Sheet 进出和数据范围切换；时长与缓动全部使用 Motion Token。
- 尊重减少动态效果设置；关闭动效后不影响信息理解。

### 逐页视觉编排

**登录 / 注册**：品牌名与一句承诺占据上部留白；表单直接落在页面上，不使用居中白卡包裹。主按钮靠近表单结束位置，注册/登录互转为低强调文字入口。

**今天**：不使用标准 App Bar。顶部安全留白后直接进入日期与状态判断，设置作为轻量工具图标与日期对齐；中央用大标题表达“今天做什么”，训练时长和动作概览形成紧凑元信息；主按钮是首屏唯一实色焦点。下半部用周节奏细线图、Divider 和最近记录形成纵向阅读流。

**计划**：使用带“新建”操作的紧凑 App Bar。首区用带轻微品牌色 Surface 的当前计划摘要形成唯一容器；下方推荐列表回归平面排版，以目标标签、时长和动作数量帮助判断。筛选条不与页面标题争抢权重。

**进度**：使用带“筛选”操作的紧凑 App Bar。大数字、范围分段与趋势线组成首个连续画面；日历通过留白分区而非外包 Card；记录列表用日期、活动名、时长和体感建立扫描层级。

**计划详情**：计划名称、适用目标和预计时长先形成判断；动作清单用编号、Divider 和节奏标记呈现；底部只保留一个与计划状态相符的主操作。

**训练执行**：降低导航与装饰存在感；顶部是退出和总进度，中部是当前动作与计时/次数，底部是完成动作。当前动作更替产生明确但短促的过渡。

**训练总结**：顶部使用成功语义的色面但控制面积；完成分钟数为最大视觉焦点，体感和备注随后出现，保存是唯一主操作。

**设置与目标**：标准 App Bar 与平面表单；分区标题和 Divider 组织内容，危险操作单独置底并使用克制的警示样式。

## 安全区域与目标视口

- 首要验收视口为移动端 `390 × 844`，同时保证常见窄屏不横向溢出。
- 壳层提供顶部与底部安全区值并统一处理底部导航；页面选定的顶部容器只消费一次顶部安全区，禁止壳层和页面重复补偿。
- 今天页由安全留白与工具行消费顶部安全区；计划页、进度页及常规二级页由 App Bar 消费顶部安全区。
- 训练执行页不强制套用标准 App Bar，由专注式训练头部消费顶部安全区，底部操作区消费底部安全区。
- 业务页不得用魔法数字模拟安全区，也不得因为需要安全区而添加没有信息职责的 App Bar。
- 键盘弹出时，登录、注册和编辑流程的当前字段与主操作可滚动到可见区域。
- 长列表与短内容页面都不能被底部导航或固定操作遮挡。

## 内容语气

- 使用具体、短句和行动语言，例如“开始 15 分钟”“本周已完成 2 次”。
- 避免空泛口号、竞技命令和羞耻表达，例如“不能再懒了”“连续记录已中断”。
- 中断或少量完成时使用中性反馈，例如“已保存完成的 8 分钟”。
- 数字结论必须说明时间范围，避免“完成率 82%”却不知道统计周期。

## 本地数据与确定性

- 账号、设置、当前计划、进行中会话和活动记录全部保存在浏览器本地存储。
- 内置账号：`demo`；密码：`123456`。
- 首次使用生成固定的示例计划和历史记录；不依赖随机数、网络或当前时刻以外的不确定输入。
- 正式训练与快速记录必须写入同一记录集合；进度数据从记录派生，不维护另一份静态统计。
- 刷新页面后保留登录、主题、根导航、当前计划和进行中训练状态。
- 提供原型级数据重置能力，但仅放在设置页的辅助区域，并明确说明影响范围。

## 设计系统与业务组件边界

- 按页面职责选择设计系统组件：需要标准标题/返回/页面操作时使用 App Bar，其余页面使用 Token 驱动的安全布局；底部导航、按钮、输入、分段控件、筛选、Sheet、FlowSheet、Dialog、Toast、空状态和 Divider 优先复用现有组件。
- 不设置“必须做多少自定义组件”的指标。只有当业务语义无法由现有组件清楚表达时，才创建业务组件。
- 预计保留两类业务组件：周活动节奏图、训练/活动趋势图；日历优先复用设计系统，确认不满足再做业务封装。
- 所有业务组件只消费现有颜色、字体、间距、圆角、边框、阴影和动效 Token；不得写入自造视觉常量，也不得复制一套私有组件规范。
- 页面丰富度主要来自编排，而不是增加组件种类或容器数量。

## 已否决的方案

- **四底部 Tab**：我的页使用频率和任务价值不足以占据根导航，且与设置内容重复。
- **计划页“我的计划 / 推荐”主标签**：两者不是互斥任务，切换增加理解成本；改为当前计划固定首区、推荐内容连续浏览。
- **记录页“日历 / 训练记录”主标签**：日历与记录本应协同过滤，不应互相隐藏；改为同页联动。
- **统计作为独立三级页**：关键进度应在根级直接可见，不能藏在记录之后。
- **每段内容一个 Card**：会削弱层级并造成视觉同质；仅保留有明确边界意义的容器。
- **静态控件模拟交互**：不实现的搜索、标签或计时器不进入可见界面。
- **用 App Bar 代替安全区域设计**：安全区是所有页面必须满足的布局边界，但顶部组件应由页面任务决定。

## 验收信号

产品与体验达到以下标准后，才视为重构完成：

- 首次进入今天页时，用户无需探索即可在 10 秒内指出主操作和预期结果；
- 今天、计划、进度三个根页面能分别用一句不重叠的话解释；
- 任一根页面都不存在“底部主 Tab + 页面内一级 Tab + 更深层 Tab”的导航堆叠；
- 根页面顶部和底部在目标视口下不与系统安全区域或导航重叠；
- 今天页在不使用标准 App Bar 的情况下仍正确消费顶部安全区域；
- 所有可见按钮、分段控件、筛选、日期和列表项都有真实且可观察的效果；
- 完成训练或快速记录后，今天与进度使用同一份数据同步更新；
- 中断训练后可以恢复，删除记录后可以撤销；
- 任一根页面首屏只有一个最高视觉焦点，不出现连续三块同权白色 Card；
- 浅色与深色主题均使用 Token 保持层级、对比度与语义一致；
- 登录、注册、选择计划、完成训练、快速记录、查看进度和调整目标形成完整可演示闭环。

## 实施基线

本方案已经给出单一方向，没有保留会改变根导航、核心闭环或视觉语言的分叉。原型重构与验收均以本文为准；实施阶段可以调整不影响上述原则的微观文案、间距和组件组合。
